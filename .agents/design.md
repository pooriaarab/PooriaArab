# Pooria Arab Design Guide

## Overview

This repository is a GitHub profile README. GitHub controls its rendering. Keep
the profile readable, compact, and useful to technical visitors. Do not infer a
product design system from this repository.

## Colors

No first-party color palette is defined. Inherit GitHub’s light and dark theme
colors. The social badges and profile-view counter use third-party colors.
Never promote those colors into personal brand tokens.

## Typography

Use Markdown headings, paragraphs, and lists. Inherit GitHub’s font stack and
type scale. Use inline code for repository names, commands, and technical terms.
Do not add web fonts or image-based text.

## Layout

Keep content in one left-aligned reading column. Use short sections and simple
lists. Separate major groups with Markdown headings or horizontal rules. Let
GitHub handle width, spacing, and responsive behavior.

## Elevation & Depth

Use a flat document structure. The profile defines no shadows, overlays, or
layered surfaces. Do not simulate depth with decorative images.

## Shapes

Use the shapes supplied by GitHub and external badge providers. No first-party
corner radius, icon geometry, or logo shape is defined. Prefer plain Markdown
over decorative frames.

## Components

The available components are headings, paragraphs, links, lists, badges, a
profile-view counter, and a contribution graph. Keep project links scannable.
Treat external widgets as optional supporting content.

## Do's and Don'ts

- Do preserve the “Vibing everyday” profile line.
- Do use exact project names and direct repository links.
- Do keep the page useful in light and dark GitHub themes.
- Don't invent a logo, palette, font, spacing scale, or application shell.
- Don't treat social-network colors as Pooria’s own palette.
- Don't add a `/brand` or `/design.md` route without an owned production site.
